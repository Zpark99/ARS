## 3. 핵심 결정 5개

1. **평가 앱 → 커뮤니티로 피벗, 평점은 정보 탭으로 강등** (#71, 08월). 랭킹 3종·마이페이지 폐기, 앨범을 "평가 대상"이 아니라 홍보·갤러리·반응이 모이는 허브로. 이후 모든 화면 재설계의 기준점.
2. **브랜치 3단계 + 질문 → 승인 시 머지, 승격은 merge commit** (#76 08/23 → #168 10/09). develop이 한 번도 만들어진 적 없던 상태를 발견하고 전환. squash 승격이 매번 계보를 끊어 충돌을 내는 것을 두 번 흡수한 뒤에야 원인이 "방식"임을 인정 → merge commit으로 고정, 이후 4회 연속 CLEAN.
3. **권한은 DB에서 막고, 불변은 트리거로** (#125 10/08 → 021 10/13). "버튼을 숨겼으니 괜찮다"던 자리를 비관리자 JWT로 실제로 뚫어 본 뒤 RLS `WITH CHECK`를 **추가가 아니라 교체**. `WITH CHECK`는 OLD를 못 보므로 컬럼 불변(board_type·artist_id)은 `BEFORE UPDATE OF` 트리거로.
4. **데이터 소스는 교체하지 않는다** (#151, 10/08 → 10/11). MusicBrainz = 신원(mbid, 라우트·DB·가드에 결합) 유지 + 커버·메타는 Apple(iTunes Search API, barcode 1:1 매칭) 보강 레이어. ip3-archive(스크래핑)·Discogs(제한 데이터) 탈락, Spotify는 링크백·로고 의무로 Apple에 밀림.
5. **거짓 UI 금지 + 작업 선정은 사용자 간트 묶음** (#160 09/28, [마감-1] 10/12~). 저장 안 되는 기능은 "준비 중"으로 노출. v1.1 백로그에서 임의로 고르지 않고 사용자가 지정한 묶음([마감-1]·[마감-2]·[마감-3]) 안에서만 진행.

그 외: 다크 단일 테마(#113) · 문서 Notion → `docs/` 일원화, 기획본은 archive에 원형 보존(#141) · 폴리모픽 `target_type`은 테이블과 1:1(#149) · 프로덕션 확인이 남은 이슈는 승격 PR에 `Closes` 안 넣음(#167).
