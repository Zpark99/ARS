### #151 앨범 데이터 소스 검토 완료 (10/08) — 결론: 교체 없음
- **결론**: `MusicBrainz = 신원(identity) 백본 유지` + `Spotify = 커버·메타 보강 레이어`. **교체 아님.** 실제 구현은 v1.1 별도 이슈
- **MusicBrainz를 유지하는 이유**: `mbid`가 라우트(`/album/[mbid]`)·DB·UUID 가드(#109)에 이미 결합돼 있어 교체하면 뿌리 전체를 바꿔야 한다 → 비용·리스크 과다. 보강 레이어 방식은 라우트·DB·가드 구조를 안 바꾸면서 체감 품질(커버 공백)만 개선
- **Spotify 도입 전제 조건**: 앨범·아티스트 Spotify 페이지로 **링크백 필수** + **Spotify 로고로 출처 표시 의무**, 커버아트 **원본 비변형**(크롭·오버레이·로고 삽입 금지), client secret은 서버 전용 환경변수. 2026-02 변경으로 `Get Several Albums` 엔드포인트와 앨범 `label`·`popularity` 필드가 삭제된 점도 설계 전제

- **Discogs 보류**: 데이터가 CC0와 "제한 데이터"로 갈리고, 제한 데이터는 상업적 목적 사용 불가
- **"국내 앨범이 꽉 찬 소스"는 합법 공개 API만으로는 도달 불가** — 멜론·지니·플로는 공개 API가 없고 국내 레이블·애그리게이터 경로로 카탈로그를 받는다. 다만 Spotify에 유통된 한국 앨범은 MusicBrainz보다 커버·메타가 양호
- **연관 이슈 연결**: #101(아티스트 매칭 갭 22%) · #117(mbid upsert) · #130(장르·발매연도 필터)에 결정 참조 코멘트를 달아 **데이터 정합 클러스터의 선행 판단**으로 고정

## 결정 (이번 주 확정된 것만)

- **권한은 DB에서 막는다** — UI 버튼 숨김은 게이트가 아니다. 권한 작업은 RLS `WITH CHECK`까지 내려가야 끝난 것으로 본다 (#125)
- **UPDATE 정책엔 `WITH CHECK`를 반드시 명시** — `USING`만 두면 신규 행 검사를 `USING`이 겸해 "내 행이면 값 바꿔치기 가능"이 된다. 기존 UPDATE 정책들도 같은 기준으로 재점검 대상 (#125)
- **권한 정책은 추가가 아니라 교체** — 같은 cmd의 PERMISSIVE 정책은 OR로 합쳐지므로, 느슨한 정책을 남긴 채 엄격한 정책만 더하면 안 막힌다. 단일 트랜잭션으로 DROP~CREATE (#125)
- **뚫림은 실증으로 확인하고, 검증 행은 롤백으로 지운다** — 단일 Supabase라 "만들고 삭제"는 프로덕션에 흔적을 남길 위험이 있어 트랜잭션 롤백 방식을 기본으로 (#125)
- **관리자 지정 = Supabase 콘솔 수동 `UPDATE`** — 운영자 1명, 코드 경로 0. `album_requests` 관리자 확인을 콘솔 수동으로 결정한 #153과 같은 방식 (#125)
- **데이터 소스는 교체하지 않는다** — MusicBrainz 신원 백본 유지 + Spotify 보강. 구현은 v1.1 (#151)
