## 1. 개요 (Overview)

- **목적**: ARS 목적 변경 → 음악 커뮤니티·홍보 플랫폼으로 피벗, 디자인 고도화
- **핵심 취지**: 음악 평가(디깅) 기반 → **음악 유저 커뮤니티·홍보 사이트**로 전환
- **증명하려는 역량(포트폴리오)**: (1) 전 대비 디자인이 깔끔한가 (2) 목적대로 기능을 구현하는가(피벗) (3) 문서 체계를 보기 쉽게 완성했는가

## 2. 문제 정의 (Problem)

### 2.1 데스크리서치

**2.1.1 SWOT 분석**

| 강점 (S) | 약점 (W) |
|---|---|
| 코드 재사용 | 1인 개발 / 음악 데이터 자체 보유 없음 |
| **기회 (O)** | **위협 (T)** |
| 인디·신인 뮤지션의 홍보 채널 수요 / 디시식 갤러리 UX가 국내 유저에 친숙 / "커뮤니티 + 홍보" 결합 틈새 | 앨범 이미지·음원 저작권 → 사이트 운영 후 의견 들어오면 그때 인지(경험 부재) |

**2.1.2 3C 분석**

- **Customer(고객)**: 두 축 모두 참여자.
  - 파는 사람 — 인디·신인 뮤지션, 창작자
  - 얘기하고 싶은 사람 — 음악을 좋아하는 모두 · 소비자 · 커뮤 중독자
- **Competitor(경쟁사)**:
  - **디시인사이드 음악 갤러리**: 가장 이상적인 커뮤니티의 구조이지만 건강하다고 보기 힘듬.
  - **익평삼 아카이브**: 벤치마킹한 사이트
  - **밴드/뮤지션 커뮤니티(예: 뮬 등)**: 장비·거래 중심, 그 외 음악 사이트들은 디깅의 형식이 강함
  - **SNS 홍보(X·인스타·유튜브)**: 파편화·휘발성. 앨범 단위로 모이지 않음.
  - **차별점**: 앨범/가수를 개체(허브)로 삼아 홍보글·갤러리·반응이 그 아래 모인다.
- **Company(자사)**: 1인 포트폴리오. 데이터·자본 열세지만 v1 재사용 자산 + 피벗 통찰 + 앨범 허브 구조로 승부.

### 2.2 문제 발굴

| 문제 | 타깃 | 솔루션 |
|---|---|---|
| 유입되는 유저들이 벽을 느낌 | 신규 가입자 | 음악을 몰라도 커뮤니티를 즐길 수 있게 피벗 |
| 신인·인디의 홍보 채널이 SNS로 파편화·휘발됨 | 인디·신인 뮤지션 | 앨범 단위 홍보게시판(양식 고정) |
| 앨범/가수를 두고 얘기 나눌 정제된 공간이 없음 | 팬·리스너 | 앨범 허브 + 디시식 갤러리 |
| 최신 평가 나열뿐이라 "지금 뜨는 것"이 안 보임 | 신규 방문자 | 월간 TOP/HOT + 실시간 피드 |

### 2.4 문제 최종 정의

**2.4.1 우선순위 결정 (MoSCoW)** — 대장의 승계/폐기 표에 직접 매핑

- **Must**: 홈 피드(월간 TOP/HOT + 실시간) · 갤러리(디시식) · 홍보게시판 · 앨범 허브 · 팔로우/팔로잉
- **Should**: 좋아요·댓글(polymorphic 승계) · 공개 프로필 · 알림
- **Could**: 평점(앨범 상세 부가로 강등) · 업데이트/공지 · Q&A
- **Won't(이번엔)**: 랭킹 3종(폐기) · 마이페이지(프로필 흡수) · 실시간 채팅 · 음원 스트리밍

## 3. 해결 방안 (Proposed Work)

### 3.1 솔루션 정의

앨범·가수를 **평가 대상이 아니라 활동이 붙는 개체(허브)**로 재정의하고, 그 위에 **홈 피드·갤러리·홍보게시판**을 얹어 방문자를 참여자로 전환한다. 평점은 축에서 내려 앨범 상세의 부가기능으로만 남긴다.

### 3.2 AS-IS / TO-BE

| 축 | AS-IS (v1) | TO-BE (피벗) |
|---|---|---|
| 컨셉 | 평가 축적(디깅) | 커뮤니티 활동·홍보 |
| 참여 주체 | 디거(생산자)만 재밌음 | 방문자도 참여자 |
| 앨범 역할 | 평가 대상 | 활동이 붙는 개체(허브) |
| 홈 | 최신 평가 리스트 | 월간 TOP/HOT + 실시간 피드 사이드바 |
| 평점 | 핵심 축 | 앨범 상세 부가기능으로 강등 |
| 랭킹 | 3종(평점 기반) | 월간 TOP/HOT 하나로 대체 |
| 프로필 | 마이페이지 + 공개 프로필 분리 | 공개 프로필로 통합(자기소개·팔로워·팔로잉) |
| 디자인 | 미니멀 다크(평가 리스트) | 익카이브식 홈 + 디시식 갤러리, 21st.dev 스타일 |

## 4. 가설 및 지표

### 4.2 고객 정의 (Persona)

- **P1 (1순위) — 인디·신인 뮤지션**: 25세, 첫 EP 발매. 홍보할 채널이 SNS뿐이라 금방 묻힘. "내 앨범을 앨범 단위로 알리고 반응을 모으고 싶다"가 핵심.
- **P2 — 음악 덕후 리스너**: 22세. 좋아하는 아티스트/앨범 얘기를 나눌 정제된 공간을 찾는다. 디시 갤러리는 산만하고 SNS는 흩어짐. 반응하고 팔로우하며 흐름을 타고 싶다.

### 4.3 마케팅 메시지

- **핵심 카피**: "음악으로 재밌게 노는 곳"
- **톤**: 음악 커뮤니티 특유의 가볍고 빠른 톤. 홍보게시판은 `[팀이름] 그외 제목은 자유` 제목 양식으로 통일해 정제감 확보.

## 5. 기능적 요구사항 (Functional Requirements)

> 대장의 승계/폐기 표를 우선순위별 F-리스트로 변환.

| 기능 ID | 기능명 | 설명 | 우선순위 | 출처(대장) |
|---|---|---|---|---|
| F-01 | 홈 피드 | 월간 TOP/HOT + 실시간 피드 사이드바 (익카이브 레퍼런스) | High | 🆕 신규 |
| F-02 | 갤러리 | 디시식 카테고리 구조. 진입 시 실시간 미디어로 분량 확보 | High | 🆕 스키마 재설계 |
| F-03 | 홍보게시판 | `[팀이름] ~~합니다` 제목 양식 고정 (board_type 확장) | High | 🆕 board_type |
| F-04 | 앨범 허브 | 아카이브 재정의 — 앨범을 활동이 붙는 개체(카탈로그/허브)로 | High | 🟡 변형 |
| F-05 | 팔로우/팔로잉 | 팔로우 + 팔로잉(신규) · 실시간 피드 동력 | High | 🆕 팔로잉 추가 |
| F-06 | 좋아요 | polymorphic — 갤러리·홍보글 공통 | Mid | 🟢 승계 |
| F-07 | 댓글 | polymorphic — 전 게시판 공통 | Mid | 🟢 승계 |
| F-08 | 공개 프로필 | 자기소개글·팔로워·팔로잉 (마이페이지 흡수) | Mid | 🟢 승계+확장 |
| F-09 | 알림 | 팔로우/팔로잉·댓글·업데이트 내역 알림 | Mid | 🆕 신규 |
| F-10 | 업데이트·공지 / Q&A | 업데이트·공지사항 내역, Q&A 게시판 | Low | 🟢 승계 |
| F-11 | 평점 | 앨범 상세 부가기능으로만 노출 (홈 축에서 제외) | Low | 🟡 강등 |
| F-12 | 로그인 | Supabase Auth | — | 🟢 승계 |

**F-01 상세 — 월간 TOP/HOT 계산**
- **TOP**: 월간 집계 뷰(평점·활동 기반). 평점 우선
- **HOT**: 월간 집계 뷰(평점·활동 기반). 투표자 수 우선. UI는 소수점 첫째자리까지 노출하되, 실제 계산은 필요 시 소수점 자리를 늘려 타이브레이킹.

**핵심 유즈케이스 시나리오**

인디 뮤지션이 새 EP를 발매 → **홍보게시판**에 `[팀이름] 새 EP 발매했습니다` 작성 → 방문자가 홈 **실시간 피드**에서 발견 → **앨범 허브**로 진입해 **좋아요·댓글**로 반응 → 마음에 들면 **팔로우** → 다음 발매 때 **알림**으로 재방문. (평가 없이도 참여 루프가 돈다.)

## 6. 비기능적 요구사항 (Non-Functional Requirements)

- **성능**: 페이지 로드 2초 이내 / 피드·갤러리 목록 페이지네이션 (Supabase 1000행 한계 대비 커서/범위 기반)
- **동시 접속자 수 (가정)**: 동시 50명 목표
- **보안**: Supabase RLS 전 테이블 적용 / 비로그인 남용 방지 / 좋아요·댓글 polymorphic RLS 정책 정합성 (v1 잔여 이슈 정리)
- **안정성**: likes 동시성(TOCTOU) 안정화 승계 / 갤러리 스키마 마이그레이션 롤백 계획 / board 삭제 정합성
- **확장성**: board_type 확장 가능한 구조 / 카테고리 추가 가능한 갤러리 스키마

## 12. Q&A (자문자답 — 리뷰어 방어용)

| 직무 | 예상 질문 | 답변/메모 |
|---|---|---|
| 기획 | 왜 피벗했나? | 홈페이지가 재미가 없고 디자인이 밋밋함. |
| 기획 | 기존 커뮤니티(디시 등)와 뭐가 다른가? | 앨범/가수를 개체(허브)로 삼아 홍보·반응이 그 아래 모인다. 갤러리(자유형식) + 홍보게시판(고정형식)으로 커뮤니티와 홍보 공간을 따로 나눠 내용 정제 |
